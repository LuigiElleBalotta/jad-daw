# UI shell: design

Sub-project 2 of 7. Status: draft for review. Date: 2026-10-07.

## 1. Purpose

A first usable window for JAD Daw on top of the Core (sub-project 1): open a project, see its tracks and regions,
edit them, mix, play, undo. Every edit goes through the same JSON commands the MCP server and the AI assistant
will use later, so the UI adds no second path into the model.

Success criteria:

- `jad-daw` opens a `.lpc` folder (for example the one made by `lpc-cli demo`), shows tracks, regions and the mixer,
  plays it on the default audio device and saves it.
- Moving a region, changing a fader, pan, mute or solo, adding or removing a region (also by dropping a WAV file),
  and undo/redo all work and match what `lpc-cli info` reports afterwards.
- The Core still builds and tests without Qt (`LPC_BUILD_UI=OFF`).
- Windows first; the same code builds on macOS in CI.

Out of scope: MIDI editor, audio editor, region resize/split/copy, region looping, automation, plugins, the
shortcut-remapping screen, the AI assistant, MCP, DAWproject import/export (see 9).

## 2. Decisions already taken

Qt 6 LTS with Qt Quick (QML). Qt is obtained with `aqtinstall` (also in CI, Windows and macOS). Inter font,
dark iPad/iOS-style theme from `design/tokens.json` (`ui/qml/Theme.qml` is generated by `tools/gen-theme.mjs`),
original icons from `assets/icons`, app icon `assets/branding/app-icon.*`. Licence AGPLv3 (Qt is used under LGPLv3
as shared libraries).

## 3. Structure

New directory `ui/`, option `LPC_BUILD_UI` (default OFF until Qt is found), target `jad-daw`.

1. `ui/bridge/` (C++ with Qt, no domain logic)
   - `ProjectController`: owns `AudioEngine`, `MediaStore`, `ProjectHost` and the audio device (reusing the JUCE
     backend of the CLI). Invokable from QML: open, save, undo, redo, play, stop, locate, `submit(commandJson)`.
     Properties: project name, playing, position, loop, master peak, degraded flag, last error.
   - `TrackListModel`, `RegionModel`, `MixerModel`: `QAbstractListModel`s rebuilt from a `Project` snapshot.
2. `ui/qml/`: design-system components (button, fader, knob, panel, icon) and views (transport bar, track list,
   timeline, mixer). Views read only from the models; every change is a command.
3. `ui/shortcuts/`: action id to key sequence. Defaults in `ui/shortcuts/default-shortcuts.json`, per-user override
   in the application data folder. Stable ids such as `transport.playStop`.

### Core change (the only one)

`ProjectHost::setChangeListener(std::function<void(std::uint64_t revision)>)`. The project thread calls it after
every accepted command, undo, redo and after a rebuild (`degraded()` going back to false). It runs on the project
thread, so it must only post to another thread. The controller posts to the Qt thread with
`QMetaObject::invokeMethod(..., Qt::QueuedConnection)`, takes a snapshot with `host.read()` and updates the
models. Revisions only grow; the controller drops a snapshot older than the one it already shows.

Why not polling or a second copy of the project: polling wastes work and adds latency; a second copy is two
sources of truth, which is what the thread architecture avoids.

## 4. Window

One fixed layout.

- Top: transport bar (play/stop, position in bars and in seconds, tempo, loop on/off, undo, redo, an indicator
  when the audio device is not running).
- Left: track list (name, colour, kind icon). Centre: timeline. Bottom: mixer, collapsible.
- Menu: File (New, Open, Save, Quit), Edit (Undo, Redo, Delete).

Timeline:

- Ruler in bars; zoom with Ctrl+wheel, scroll with wheel and Shift+wheel.
- Regions are rectangles in the track colour. Audio regions draw a simple waveform preview (peak data computed
  once per media item on a worker thread, cached in the project's `cache/` folder).
- Click selects, Shift+click extends. Dragging a region shows it moving locally and sends one `move_region`
  on release (one undo step). Snap to a quarter of a bar by default.
- Delete removes the selected regions as one transaction.
- Dropping a WAV file on a track creates `add_media` (copy into `audio/`) and `add_region` in one transaction.
  Only 48 kHz files matching the project rate are accepted until the Core resamples; others show an error.

Mixer: one strip per track and one for the master: fader (dB), pan, mute, solo, and a master peak meter. While a
fader is dragged the UI shows the local value and sends `set_strip` on release. Sound therefore follows the fader
only after release; the atomic value channel of Core spec section 4 is not built (see the Core review rulings).

## 5. Errors

- A rejected command (`CommandError`) shows a non-blocking message at the bottom with its message. The model is
  unchanged, so the UI stays consistent.
- Opening an invalid project shows the loader's message in a dialog. Missing media: the region is drawn crossed
  out and plays silence.
- `ProjectHost::degraded()` true: the transport bar shows "audio not running"; the next successful rebuild
  clears it.

## 6. Shortcuts (Logic defaults)

Space play/stop, Return go to start, Ctrl/Cmd+Z undo, Shift+Ctrl/Cmd+Z redo, Ctrl/Cmd+S save, Ctrl/Cmd+O open,
Delete remove region, M mute, S solo, C loop, plus and minus zoom. Ctrl on Windows, Cmd on macOS. The user file
overrides single actions; unknown ids and clashes are reported and ignored.

## 7. Tests

- Bridge and models: QtTest against the real Core, no window (open demo project, submit commands, check models,
  undo/redo, rejected command leaves models unchanged, stale revision is dropped).
- Views: `qmltestrunner` with `QT_QPA_PLATFORM=offscreen` (drag creates exactly one command; Delete creates one
  transaction; fader drag sends on release only).
- Core: a test for the change listener (called once per accepted change, with growing revisions, also after
  rebuild; never called for a rejected command).
- CI: install Qt with aqt on Windows and macOS, build with `LPC_BUILD_UI=ON`, run the above.

## 9. Interchange with other DAWs (DAWproject), decision

The native format stays the `.lpc` folder (atomic saves, streaming media, schema migrations). For moving projects
between DAWs we add **import and export of the open DAWproject format** (`.dawproject`, a zip with `project.xml`,
`metadata.xml` and the audio files), as its own sub-project 7 in the Core layer (`lpc::dawproject`), after the UI
shell: it needs no Qt, can be tested by round trip against the Core model, and the UI then only adds File >
Import/Export entries. Known gaps to document there: our built-in processors have no DAWproject equivalent;
automation is stored but not played; features DAWproject carries that the model lacks are dropped with a report.
The exact element mapping is written in that sub-project's spec after reading the published schema, not from memory.
